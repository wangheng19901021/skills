# 手动忽略决策规则

AI 审查标出的警告，默认全部修复。确需手动忽略时，必须先回答以下四个问题，全部答出才允许忽略，缺一个就停。

## 决策树

1. **最坏会怎样？** 必须说出明确的后果上限，且覆盖所有已知触发条件（包括凌晨批量任务、大促等非日常场景）。说不出 → 回去读代码，禁止忽略。
2. **为什么现在不能修？** "来不及"必须指着具体约束条件说（QA 排期、依赖接口未 ready、灰度窗口已过）。指不出 → 判定为"不想修"，马上修。
3. **谁来拍板？** 由对这段代码系统上下文最熟的人拍板——同时掌握业务流程、数据库约束、运维窗口三个维度。不是职级最高的人，也不是代码作者。没人同时掌握 → 禁止忽略。
4. **怎么保证不会忘？** 在点忽略的当下，PR 评论 @负责人 + 预计修复时间 + 最小修复方案，代码对应位置加 `TODO(#规则ID)` 注释。没有指定负责人和截止时间 → 禁止合并。

## 速查表

| 问题 | 核心检验 | 不通过就停 |
|------|---------|-----------|
| 最坏会怎样？ | 能否说出明确的上限后果，且覆盖所有已知触发条件？ | 说不出→读代码 |
| 为什么不能现在修？ | 能否指着具体约束条件说？ | 指不出→马上修 |
| 谁来拍板？ | 这个人对这段代码的上下文熟不熟？ | 不熟→找最熟的人 |
| 怎么保证不忘记？ | 是否在当下就指定了负责人和截止时间？ | 没有→别合 PR |

## PR 评论模板

被忽略的每条警告下面，必须回填以下模板：

```markdown
**忽略原因**：
**最坏后果**：（明确上限，覆盖所有已知触发条件）
**为什么现在不能修**：（具体约束条件）
**负责人**：@xxx
**预计修复时间**：YYYY-MM-DD HH:mm
**最小修复方案**：
**TODO**：// TODO(#规则ID): 说明
```

## 反例

- "这个接口 QPS 很低，并发冲突概率可以忽略。"——只看了日常流量，漏了凌晨批量任务瞬间 800 并发，`HashMap` 被并发写坏，同步链路阻塞四十分钟。
- "先上线，回头再补。"——没有负责人和截止时间，两周后上下文烂在记忆里，"回头补"变成一行永远不会有人看的 TODO。

## 正例

```markdown
**忽略原因**：权限服务重启，业务校验层不可用，数据库约束完整兜底。
**最坏后果**：订单状态停留在"待支付"，5 分钟后自动补偿重查，最多一张客服工单。
**为什么现在不能修**：QA 排期到明天，用户已等待 2 小时。
**负责人**：@老周
**预计修复时间**：2026-07-16 18:00
**最小修复方案**：权限服务恢复后，回调先走正常校验，校验失败且依赖不可用才降级直写库。
**TODO**：// TODO(#transaction-rule-05): 评估 500ms 豁免是否需要长期保留
```

## 配套机制（非 Claude Code 原生功能）

`TODO(#规则ID)` 注释与 PR 评论的联动，依赖团队自建的 Skill 规则：AI 下次扫描同一段代码时，把 TODO 注释和 PR 评论一起重新标出。不用人记得，AI 帮你追。
